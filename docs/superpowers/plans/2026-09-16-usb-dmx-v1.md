# USB DMX V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a release-ready HACS integration that exposes GUI-managed DMX dimmers and raw channels through a local DMX USB Pro protocol interface.

**Architecture:** One config entry owns a typed runtime containing a single controller and backend. Entities mutate a locked 512-byte controller buffer; a serialx-based backend sends complete DMX USB Pro frames and the controller owns transitions, availability, and reconnect.

**Tech Stack:** Python/Home Assistant 2026.9.2, serialx 1.10.0, pytest-homeassistant-custom-component 0.13.365, pytest, Ruff, hassfest, HACS validation.

**Spec:** `docs/superpowers/specs/2026-09-16-usb-dmx-design.md`

## Global Constraints

- Domain is `usb_dmx`; integration display name is `USB DMX`.
- Runtime version is `0.1.0`; minimum Home Assistant is `2026.9.0`.
- Home Assistant OS on amd64 and aarch64 is the primary target.
- V1 supports only DMX USB Pro protocol over serialx; no generic USB VID/PID discovery.
- No Art-Net, sACN, OLA, MQTT, add-on, external service, host package, or shell command at runtime.
- Controller buffer starts with 512 zero bytes and is its sole mutable owner.
- All production behavior follows test-first RED/GREEN/refactor cycles.
- Every task ends with a Conventional Commit pushed directly to `main`.
